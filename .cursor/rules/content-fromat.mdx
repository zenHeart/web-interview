# 内容格式化规则

## 描述
规范文档内容格式和组件使用方式，确保项目风格一致。

## Markdown格式
- 主题名称使用一级标题(#)，问题使用二级标题(##)
- 代码块必须指定语言
- 使用制表符而非空格进行缩进
- 列表项使用 * 而非 - 标记
- 表格需要对齐，标题行下方必须有分隔线

## 组件使用
- `<Answer>`: 包裹答案内容，支持meta属性
- `<Sandpack>`: 用于展示可交互代码示例
- `<TestCode>`: 用于展示测试用例
- `<Tabs>/<TabItem>`: 用于分类展示不同内容
- `<details>/<summary>`: 用于折叠大段代码
- `<CodeBlock>`: 用于展示代码块，支持高亮和滚动

## 特殊语法
- 使用`:::tip:::`创建提示框
- 使用`:::warning:::`创建警告框
- 使用`:::note:::`创建注释框

## 答案结构
答案应包含以下部分：
1. 核心概念解释
2. 详细内容说明
3. 示例代码（必要时）
4. 延伸阅读资源

## 代码示例格式
```md
<Answer meta={{difficulty: "中级", duration: "5分钟"}}>

1. **核心概念**
   * 首先解释核心概念

2. **详细说明**
   详细内容...

3. **代码示例**
```js
// 示例代码
```

**延伸阅读**
* [资源名称](mdc:资源链接) 资源描述

</Answer>
```

## 图片和资源
- 图片应放在与主题相关的assets目录中
- 图片引用使用相对路径
- 所有外部资源必须有明确的引用说明

提议需兼容现有模版
