## AI 赋能升级 MVP - 日度任务列表 (Markdown 版)

### **第一部分：实现 “AI 代码自动评估” 功能 (预计 6 天)**

#### **Day 1: 后端改造与基础准备**

* **今日目标:** 准备好存储和触发评估所需的数据结构与接口。
* **子任务:**
  * `[ ]` 在 `submissions` (或类似的) 数据表中，增加两个字段：
    * `unit_test_results` (JSON 类型, 用于存储测试用例通过情况)。
    * `ai_review_report` (JSON 类型, 用于存储 LLM 返回的分析报告)。
  * `[ ]` 在后端创建一个新的、空的 API 端点 `POST /api/submissions/{submission_id}/evaluate`。当前它只需要能被调用，返回一个 `{"message": "Evaluation started"}` 即可。
  * `[ ]` 修改现有的“提交代码”接口逻辑，使其在保存完候选人代码后，能够异步触发对上述新接口的调用。
* **✅ 验证标准:**
    1. 通过数据库管理工具，可以清晰地看到 `submissions` 表中存在新增的两个字段。
    2. 通过 Postman 或 curl 调用 `POST /api/submissions/{submission_id}/evaluate` 接口，能够收到 `200 OK` 和预设的成功消息。
    3. 完成一次代码提交，能从后端日志中看到 `evaluate` 任务已被触发的记录。

#### **Day 2: 核心功能一：单元测试沙箱集成**

* **今日目标:** 实现对候选人代码的安全执行和结果判断。
* **子任务:**
  * `[ ]` 为一道已知的编程题，手动编写 2-3 个简单的测试用例 (例如，`assert(myFunction(2, 2) === 4)`)。
  * `[ ]` 集成一个代码执行沙箱（推荐 `judge0` 或基于 Docker 的轻量级方案）。
  * `[ ]` 开发一个独立的函数 `runUnitTests(code, testCases)`，该函数接收候选人代码和测试用例字符串，返回一个 JSON 对象，如 `{"passed": 2, "total": 3, "details": [...]}`。
* **✅ 验证标准:**
    1. 直接调用 `runUnitTests` 函数，传入一份正确的代码，返回结果为全部通过。
    2. 直接调用 `runUnitTests` 函数，传入一份错误的代码，返回结果为部分或全部失败。
    3. 函数能处理超时或运行时错误等异常情况，而不是直接崩溃。

#### **Day 3: 核心功能二：AI 代码评审逻辑**

* **今日目标:** 实现调用 LLM API 并获取结构化的代码分析报告。
* **子任务:**
  * `[ ]` **精心设计 V1 版的 Prompt** (这是今天的核心工作!)。明确指示 AI 分析代码的逻辑、可读性、效率、最佳实践，并强制要求它以 JSON 格式输出。
  * `[ ]` 开发一个独立的函数 `getAiReview(code, questionDescription)`，该函数调用 LLM API，并返回其生成的 JSON 分析报告。
  * `[ ]` 对返回结果进行解析和验证，确保即使 AI 返回格式稍有偏差，程序也不会崩溃。
* **✅ 验证标准:**
    1. 直接调用 `getAiReview` 函数，传入一段示例代码，能够成功打印出 LLM 返回的、结构化的 JSON 报告。
    2. 更换不同的代码（好代码/坏代码）进行测试，观察 AI 返回的报告内容是否基本符合预期。

#### **Day 4: 后端评估流程整合**

* **今日目标:** 将单元测试和 AI 评审两个功能串联起来，完成整个后端评估逻辑。
* **子任务:**
  * `[ ]` 完善 `POST /api/submissions/{submission_id}/evaluate` 接口的内部逻辑。
  * `[ ]` 在接口内，首先调用 `runUnitTests` 函数。
  * `[ ]` 接着，调用 `getAiReview` 函数。
  * `[ ]` 将上述两步返回的 JSON 结果，分别存入 `submissions` 表中对应的 `unit_test_results` 和 `ai_review_report` 字段。
* **✅ 验证标准:**
    1. 通过 Postman 完整调用一次 `evaluate` 接口。
    2. 调用完成后，查询数据库，确认该 `submission` 记录的两个新字段已被成功填充了真实、有效的 JSON 数据。

#### **Day 5: 前端 UI 展示**

* **今日目标:** 在现有界面上，将 AI 评估报告可视化地呈现给面试官。
* **子任务:**
  * `[ ]` 在面试官查看候选人提交详情的现有页面上，设计并开发一个新的 UI 组件（例如 "AI 分析报告" 卡片）。
  * `[ ]` 让该页面在加载时，从后端获取指定 `submission` 的完整数据（包含 AI 报告）。
  * `[ ]` 将 `unit_test_results` 和 `ai_review_report` 的 JSON 数据，渲染到新开发的 UI 组件中，使其易于阅读。
* **✅ 验证标准:**
    1. （使用假数据）UI 组件在没有后端数据时也能正确渲染其骨架和样式。
    2. 打开一个已完成评估的提交详情页，能够看到格式化后的单元测试结果和 AI 代码分析报告，内容与数据库中的一致。

#### **Day 6: 端到端联调与优化**

* **今日目标:** 确保从代码提交到报告展示的整个流程顺畅无误，并进行初步优化。
* **子任务:**
  * `[ ]` 完整地模拟一次流程：提交代码 -> 等待后台处理 -> 刷新结果页面 -> 查看报告。
  * `[ ]` 识别并修复流程中的 bug。
  * `[ ]` 为前端增加加载状态（Loading Indicator），因为 AI 分析需要时间。
  * `[ ]` （可选）优化一下 Prompt，让 AI 的输出更符合预期。
* **✅ 验证标准:**
    1. 任何一个非技术人员，都可以在你的指导下，顺利完成整个操作流程并看到最终的评估报告。
    2. 当评估正在进行时，前端有明确的“处理中”提示。

### **第二部分：实现 “AI 辅助智能组卷” 功能 (预计 4 天)**

#### **Day 7: 数据模型升级与向量化准备**

* **今日目标:** 改造现有 `Question` 数据模型，为语义搜索做准备。
* **子任务:**
  * `[ ]` 在 `questions` 表中增加 `tags` (JSON/Array) 和 `embedding` (Vector) 两个字段。
  * `[ ]` 配置向量数据库或为 PostgreSQL 安装 `pgvector` 插件。
  * `[ ]` 确保后端应用能够成功连接到向量数据库/功能。
* **✅ 验证标准:**
    1. `questions` 表结构已更新。
    2. 可以成功执行一条插入/查询向量数据的 SQL 或命令，证明数据库向量功能可用。

#### **Day 8: 存量题库 AI 增强**

* **今日目标:** 使用 AI 丰富现有全部题目的元数据。
* **子任务:**
  * `[ ]` 开发一个一次性执行的脚本 `enrich_questions.js/py`。
  * `[ ]` 该脚本遍历所有题目，调用 LLM 和 Embedding API，填充 `tags` 和 `embedding` 字段。
  * `[ ]` 执行该脚本，完成对存量数据的处理。
* **✅ 验证标准:**
    1. 脚本执行完毕后，随机抽查数据库中 5-10 条题目，确认 `tags` 和 `embedding` 字段都有值，且 `tags` 内容合理。

#### **Day 9: 后端语义搜索 API 开发**

* **今日目标:** 开发一个能根据自然语言描述返回相关题目的核心接口。
* **子任务:**
  * `[ ]` 创建新接口 `POST /api/questions/ai-search`。
  * `[ ]` 接口接收一个包含自然语言 `prompt` 的 JSON。
  * `[ ]` 接口内部逻辑：将 `prompt` 文本向量化 -> 在 `questions` 表中进行向量相似度查询 -> 返回 Top 5-10 的题目列表。
* **✅ 验证标准:**
    1. 通过 Postman 调用该接口，输入 "react hooks"，返回的题目都与 React Hooks 相关。
    2. 输入 "css flexbox aign items"，即使有拼写错误，也能返回与 Flexbox 布局相关的题目。

#### **Day 10: 前端集成与上线**

* **今日目标:** 将 AI 选题功能无缝集成到现有出题界面。
* **子任务:**
  * `[ ]` 在现有选题 UI 上，增加一个“AI 助手”输入框和一个“搜索”按钮。
  * `[ ]` 将该输入框与 `POST /api/questions/ai-search` 接口对接。
  * `[ ]` 将接口返回的题目列表，动态渲染在页面上。
  * `[ ]` 进行完整的端到端测试。
* **✅ 验证标准:**
    1. 面试官在 UI 上输入需求，点击按钮后，下方会刷新出 AI 推荐的题目列表。
    2. 整个交互流程顺畅，无明显 bug。
