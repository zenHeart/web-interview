# 工程化与构建交付 ✅

聚焦团队工程实践：项目结构、多端适配、分包/预下载、CI/CD、质量保障、监控与稳定性。

## 项目结构与多端适配如何设计？ {#P0-structure-multiend}

<Answer>

**核心概念:**

按“领域/业务模块/通用能力”分层；抽象跨端 API 与组件层，端差异通过适配器注入；保证同源代码多端产出。

**示例说明:**

```txt
src/
  adapters/ (wx/ali/bytedance)
  components/
  services/
  pages/
```

**面试官视角:**

* **要点清单**: 分层边界；端差异收敛
* **加分项**: 代码生成器/模板；依赖与版本治理
* **常见失误**: 端条件分支散落代码

**延伸阅读:**

* 各端框架工程实践

</Answer>

## 分包、独立分包与按需加载策略？ {#P0-subpackages}

<Answer>

**核心概念:**

主包+分包降低首包体积；独立分包适合活动/营销；结合预下载、按需加载与缓存优化首屏。

**示例说明:**

```json
{
  "subPackages": [
    { "root": "pkgA", "pages": ["list", "detail"] }
  ],
  "preloadRule": { "pages/index": { "packages": ["pkgA"], "network": "all" } }
}
```

**面试官视角:**

* **要点清单**: 体积/性能/更新频率权衡
* **加分项**: 动态位点分包；首包体积监控
* **常见失误**: 热路径误入分包；过度预下载

**延伸阅读:**

* [分包](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/basic.html)

</Answer>

## 小程序的 CI/CD 与自动化发布？ {#P1-cicd}

<Answer>

**核心概念:**

通过官方 CI、命令行或第三方平台完成编译/校验/上传/提审；管道内执行静态检查、单测与构建产物审计。

**示例说明:**

```bash
# CI 内调用小程序 CLI（示意）
miniprogram-ci --upload --version 1.2.3 --desc "feat: new" \
  --appid $APPID --private-key ./key
```

**面试官视角:**

* **要点清单**: 可重复、可审计、可回滚
* **加分项**: 多环境/多端联合流水线
* **常见失误**: 密钥管理不当；跳过校验

**延伸阅读:**

* 官方 CI 文档

</Answer>

## 质量保障：Lint/单测/E2E 如何落地？ {#P1-quality}

<Answer>

**核心概念:**

ESLint/Stylelint/Commitlint、Jest 单测、端 E2E(自研/端工具)；以业务关键链路定义回归集。

**示例说明:**

```json
{"scripts": {"test": "jest --coverage"}}
```

**面试官视角:**

* **要点清单**: 阶段门禁；敏捷与质量平衡
* **加分项**: 覆盖率看板；合并队列
* **常见失误**: 仅冒烟；缺端到端

**延伸阅读:**

* Jest/端侧自动化

</Answer>

## 监控与稳定性体系怎么搭？ {#P1-observability}

<Answer>

**核心概念:**

前端埋点/性能/异常/网络统一上报，结合后端采集与报警；回归实验、灰度控制与快速回滚。

**示例说明:**

```js
wx.onError(err => report({ type: 'js', err }))
wx.onPageNotFound(r => report({ type: '404', r }))
```

**面试官视角:**

* **要点清单**: 全链路指标；SLO/SLA
* **加分项**: 端特性(机型/地区)维度分析
* **常见失误**: 只有 PV/UV；无回滚

**延伸阅读:**

* 官方监控接口/自建 SDK

</Answer>
