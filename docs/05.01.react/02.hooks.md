## 说一下 useState 的使用？{#p0-useState}

<Answer>

useState 用在函数组件和自定义 Hook 中，用于声明和管理组件状态。它返回一个包含当前状态值和更新函数的数组。
useState 函数如下

```ts
type Dispatch<A> = A => void;
type BasicStateAction<S> = (S => S) | S;
function useState<S>(initialState: (() => S) | S): [S, Dispatch<BasicStateAction<S>>]
```

* initialState：初始状态值
  * 可以是任意类型，也可以是一个返回初始状态的函数。
  * 也可是函数返回一个初始值，函数只会在组件首次渲染时调用一次。
* 返回值是一个数组，第一个元素是当前状态值，第二个元素是更新状态的函数。
  * 第一个元素是当前状态值未传入 initialState 时默认为 undefined。
  * 更新函数
    * 支持直接传入新状态值
    * 也支持传入一个函数来基于当前状态计算新状态。

示例如下

```tsx live
function Counter () {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Add</button>
    </div>
  )
}
```

使用中需要注意

1. 遵守 Hooks 规则
   * 只能在函数组件或自定义 Hook 中调用 useState。
   * 不能在条件语句、循环或嵌套函数中调用 useState。
2. 对于初始状态值不要传入复杂的函数，这样会导致每次组件渲染时都重新计算初始状态。

## useReducer 的作用，和 useState 有什么区别？ {#p1-useReducer}

<Answer>

`useReducer` 是 React 提供的状态管理 Hook，适用于复杂的状态逻辑管理。它与 `useState` 的主要区别在于状态管理方式和适用场景。

**基本语法**

```ts
const [state, dispatch] = useReducer(reducer, initialState)
```

* `reducer`: 纯函数，接收当前状态和动作，返回新状态
* `initialState`: 初始状态值
* `state`: 当前状态
* `dispatch`: 分发动作的函数

**与 useState 的核心区别**

|特性|useState|useReducer|
|---|---|---|
|**适用场景**|简单状态管理|复杂状态逻辑|
|**状态结构**|单一值或简单对象|复杂对象、多个相关状态|
|**更新方式**|直接设置新值|通过动作(action)描述变化|
|**状态依赖**|适合独立状态|适合依赖前一状态的更新|
|**逻辑复用**|较难复用|reducer逻辑易于复用和测试|

**典型使用场景对比**

**useState 适合：**

```tsx
// 简单计数器
function SimpleCounter () {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(count + 1)}>增加</button>
    </div>
  )
}
```

**useReducer 适合：**

```tsx
// 复杂状态管理
type State = { count: number; error: string | null; loading: boolean }
type Action =
  | { type: 'increment' }
  | { type: 'decrement' }
  | { type: 'reset' }
  | { type: 'setError'; error: string }

function reducer (state: State, action: Action): State {
  switch (action.type) {
    case 'increment':
      return { ...state, count: state.count + 1, error: null }
    case 'decrement':
      if (state.count <= 0) {
        return { ...state, error: '计数不能小于0' }
      }
      return { ...state, count: state.count - 1, error: null }
    case 'reset':
      return { count: 0, error: null, loading: false }
    case 'setError':
      return { ...state, error: action.error }
    default:
      return state
  }
}

function ComplexCounter () {
  const [state, dispatch] = useReducer(reducer, {
    count: 0,
    error: null,
    loading: false
  })

  return (
    <div>
      <p>计数: {state.count}</p>
      {state.error && <p style={{ color: 'red' }}>{state.error}</p>}
      <button onClick={() => dispatch({ type: 'increment' })}>增加</button>
      <button onClick={() => dispatch({ type: 'decrement' })}>减少</button>
      <button onClick={() => dispatch({ type: 'reset' })}>重置</button>
    </div>
  )
}
```

**useReducer 的优势**

* **状态逻辑集中**: 所有状态变更逻辑都在 reducer 中
* **可预测性**: 通过动作描述状态变化，便于调试
* **逻辑复用**: reducer 函数可以独立测试和复用
* **复杂状态**: 适合管理包含多个字段的状态对象

**实际应用场景**

**1. 表单状态管理**

```tsx
function useFormReducer (initialValues) {
  const [state, dispatch] = useReducer(
    (state, action) => {
      switch (action.type) {
        case 'SET_FIELD':
          return { ...state, [action.field]: action.value }
        case 'SET_ERROR':
          return { ...state, errors: { ...state.errors, [action.field]: action.error } }
        case 'RESET':
          return initialValues
        default:
          return state
      }
    },
    { ...initialValues, errors: {} }
  )

  return [state, dispatch]
}
```

**2. 购物车管理**

```tsx
function cartReducer (state, action) {
  switch (action.type) {
    case 'ADD_ITEM':
      return { ...state, items: [...state.items, action.item] }
    case 'REMOVE_ITEM':
      return { ...state, items: state.items.filter(item => item.id !== action.id) }
    case 'UPDATE_QUANTITY':
      return {
        ...state,
        items: state.items.map(item =>
          item.id === action.id ? { ...item, quantity: action.quantity } : item
        )
      }
    default:
      return state
  }
}
```

**选择建议**

* **使用 useState**: 状态简单、独立、更新逻辑简单
* **使用 useReducer**: 状态复杂、有多个相关字段、更新逻辑复杂、需要基于前一状态计算新状态

**常见误区**

* **过度使用 useReducer**: 简单状态也用 useReducer 增加复杂度
* **reducer 不纯**: 在 reducer 中执行副作用操作
* **action 设计不当**: action 类型不明确或包含过多逻辑

:::tip
在简单场景下优先使用 `useState`，当状态逻辑变得复杂、难以管理时再考虑重构为 `useReducer`。
:::

## 说一下 useEffect? {#p0-useEffect}

<Answer>

useEffect 用来绑定副作用函数，如数据获取、订阅事件、DOM 操作等。useEffect 函数定义如下

```ts
type EffectCallback = () => (void | (() => void));
function useEffect(effect: EffectCallback, deps?: Array<any> | void | null): void
```

* effect：副作用函数，执行时机为组件渲染后。
  * 可以返回一个清理函数，在组件卸载或依赖项变化时调用。
* deps：依赖项数组，控制副作用函数的执行时机。
  * 如果传入空数组 `[]`，副作用函数只在组件首次渲染时执行。
  * 如果不传入 deps，则每次组件渲染都会执行副作用函数。
  * 如果传入依赖项数组，副作用函数会在依赖项变化时执行。
  * **注意不要动态改变依赖项** react 会抛出警告

使用中要注意

1. 确保副作用函数中消费的变量在 deps 中都有申明
2. 副作用函数获取的 state 为快照，如果要获取最新 state，采用回调模式消费数据，或者使用 useRef 存储最新值。特别是在回调涉及异步时间是需要尤为注意
3. 正确设置清理函数避免内存泄漏问题

## useLayoutEffect 和 useEffect 有什么区别? {#p0-useLayoutEffect}

<Answer>

`useLayoutEffect` 和 `useEffect` 的主要区别在于**执行时机**和**同步性**。

**核心区别表格**

| 特性 | useLayoutEffect | useEffect |
|------|----------------|-----------|
| 执行时机 | DOM 更新后，浏览器绘制前 | 浏览器绘制后，异步执行 |
| 同步性 | 同步执行，阻塞渲染 | 异步执行，不阻塞渲染 |
| 适用场景 | 需要立即测量 DOM、避免视觉闪烁 | 数据获取、订阅、清理等副作用 |
| 性能影响 | 可能阻塞浏览器绘制 | 不影响浏览器绘制性能 |

**执行时机详细说明**

1. **useLayoutEffect** 在 React 渲染周期中的位置：
   * DOM 更新完成 → **useLayoutEffect 执行** → 浏览器绘制
   * 同步执行，会阻塞浏览器的绘制过程
   * 适合需要立即获取最新 DOM 布局信息的场景

2. **useEffect** 在 React 渲染周期中的位置：
   * DOM 更新完成 → 浏览器绘制 → **useEffect 异步执行**
   * 不阻塞浏览器的绘制过程
   * 更适合处理副作用操作

**代码示例**

```tsx
import React, { useState, useEffect, useLayoutEffect, useRef } from 'react'

function ComparisonExample () {
  const [count, setCount] = useState(0)
  const divRef = useRef<HTMLDivElement>(null)

  // useLayoutEffect - 同步执行，在绘制前
  useLayoutEffect(() => {
    console.log('useLayoutEffect: DOM更新后，绘制前执行')
    if (divRef.current) {
      // 可以同步获取准确的DOM尺寸
      const width = divRef.current.getBoundingClientRect().width
      console.log('同步获取宽度:', width)
    }
  }, [count])

  // useEffect - 异步执行，在绘制后
  useEffect(() => {
    console.log('useEffect: 浏览器绘制后异步执行')
    // 适合数据获取、订阅等副作用
  }, [count])

  return (
    <div ref={divRef}>
      <p>计数: {count}</p>
      <button onClick={() => setCount(count + 1)}>
        增加计数
      </button>
    </div>
  )
}
```

**典型应用场景**

**useLayoutEffect 适用场景：**

* 测量 DOM 元素尺寸或位置
* 避免视觉闪烁的 DOM 操作
* 需要在浏览器绘制前同步更新的场景

**useEffect 适用场景：**

* 数据获取（API 调用）
* 设置订阅或事件监听
* 清理资源
* 不需要阻塞渲染的副作用

**常见误区**

* **过度使用 useLayoutEffect**: 大多数情况下应优先使用 `useEffect`
* **性能误解**: `useLayoutEffect` 会阻塞渲染，影响性能
* **执行时机混淆**: 不清楚两者在渲染周期中的具体位置

:::tip
通常情况下，应优先使用 `useEffect`，因为它不会阻塞浏览器的渲染。只有在需要获取最新的 DOM 布局信息并立即触发副作用时，才需要使用 `useLayoutEffect`。
:::

## useActionState 和 useFormStatus 有什么区别? {#p0-useActionState}

<Answer>

`useActionState` 和 `useFormStatus` 是 React 19 中引入的两个新 Hook，都用于处理表单相关的状态管理，但它们的用途和适用场景有明显区别。

**核心区别对比**

| 特性 | useActionState | useFormStatus |
|------|---------------|---------------|
| **用途** | 处理异步操作状态 | 获取表单提交状态 |
| **适用范围** | 通用异步操作 | 仅针对表单提交 |
| **环境限制** | React 核心 | react-dom 环境 |
| **状态管理** | 管理完整的异步操作生命周期 | 只读的表单状态信息 |
| **返回值** | `[result, action, state]` | `{ pending, data, method, action }` |

**useActionState 详解**

`useActionState` 用于管理异步操作的完整生命周期，包括挂起、成功、错误状态：

```tsx
import { useActionState } from 'react'

// 异步操作函数
async function saveData (text: string) {
  await new Promise(resolve => setTimeout(resolve, 2000))
  if (text === 'error') {
    throw new Error('保存失败')
  }
  return `保存成功: ${text}`
}

function ActionStateExample () {
  const [result, saveAction, state] = useActionState(
    async (text: string) => {
      return await saveData(text)
    },
    null // 初始结果
  )

  return (
    <div>
      <button
        onClick={() => saveAction('test')}
        disabled={state.status === 'pending'}
      >
        {state.status === 'pending' ? '保存中...' : '保存数据'}
      </button>
      {state.status === 'success' && <p>✓ {result}</p>}
      {state.status === 'error' && <p>✗ {state.error?.message}</p>}
    </div>
  )
}
```

**useFormStatus 详解**

`useFormStatus` 用于获取表单的提交状态，主要在表单组件内部使用：

```tsx
import { useFormStatus } from 'react-dom'

function SubmitButton () {
  const { pending, data, method, action } = useFormStatus()

  return (
    <button type="submit" disabled={pending}>
      {pending ? '提交中...' : '提交'}
    </button>
  )
}

function FormExample () {
  async function handleSubmit (formData: FormData) {
    // 处理表单提交
    await new Promise(resolve => setTimeout(resolve, 2000))
    console.log('表单提交完成')
  }

  return (
    <form action={handleSubmit}>
      <input name="username" placeholder="用户名" />
      <input name="email" type="email" placeholder="邮箱" />
      <SubmitButton />
    </form>
  )
}
```

**使用场景对比**

**useActionState 适用于：**

* 数据加载和保存操作
* 需要跟踪异步操作状态的场景
* 复杂的状态管理（成功、错误、挂起）
* 自定义异步操作逻辑

**useFormStatus 适用于：**

* 表单提交状态展示
* 表单验证过程中的状态管理
* 需要根据表单状态调整UI的场景
* 与 HTML 表单元素紧密配合

**实际开发建议**

1. **优先使用 useActionState**: 对于大多数异步操作，`useActionState` 提供了更完整的状态管理
2. **表单场景结合使用**: 可以在同一个表单中同时使用两个 Hook
3. **考虑兼容性**: 确保项目使用 React 19 及以上版本

**常见误区**

* **混淆使用场景**: `useFormStatus` 仅用于表单，不适用于其他异步操作
* **环境限制**: `useFormStatus` 只能在 react-dom 环境中使用
* **状态管理**: `useFormStatus` 是只读的，不能主动更新状态

:::tip
在实际项目中，建议根据具体需求选择合适的 Hook。如果是通用的异步操作，使用 `useActionState`；如果是表单相关的状态展示，使用 `useFormStatus`。
:::

**延伸阅读**

* [useActionState](https://react.dev/reference/react/useActionState) 官方文档
* [useFormStatus](https://react.dev/reference/react-dom/hooks/useFormStatus) 官方文档
* [React 19 新特性](https://react.dev/blog/2024/12/05/react-19#new-hook-useactionstate) 官方博客

</Answer>

## useSyncExternalStore 的作用? {#p2-useSyncExternalStore}

<Answer>

`useSyncExternalStore` 是 React 18 引入的 Hook，用于安全地订阅外部数据源，确保在并发模式下外部状态与 React 组件状态的一致性。

**基本语法**

```ts
const snapshot = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?)
```

* `subscribe`: 订阅函数，接收监听器并返回取消订阅函数
* `getSnapshot`: 获取当前状态快照的函数
* `getServerSnapshot`: 可选，用于 SSR 的服务端快照函数
* `snapshot`: 返回当前状态快照

**核心作用**

|功能|说明|使用场景|
|---|---|---|
|外部状态订阅|安全订阅 React 外部的数据源|状态管理库、浏览器 API|
|并发安全|确保并发模式下状态一致性|高频更新、复杂状态|
|替代 useEffect|消除手动订阅的副作用需求|外部数据源集成|

**典型使用场景**

**1. 订阅自定义状态管理器**

```tsx
import React, { useSyncExternalStore, useMemo } from 'react'

// 创建简单的状态管理器
function createStore (initialValue: number) {
  let value = initialValue
  const listeners = new Set<() => void>()

  return {
    // 订阅函数
    subscribe: (listener: () => void) => {
      listeners.add(listener)
      return () => listeners.delete(listener) // 返回取消订阅函数
    },
    // 获取快照
    getSnapshot: () => value,
    // 更新状态
    increment: () => {
      value += 1
      listeners.forEach(listener => listener())
    }
  }
}

function Counter () {
  const store = useMemo(() => createStore(0), [])

  const count = useSyncExternalStore(
    store.subscribe,
    store.getSnapshot
  )

  return (
    <div>
      <p>计数: {count}</p>
      <button onClick={() => store.increment()}>增加</button>
    </div>
  )
}
```

**2. 订阅浏览器 API**

```tsx
function useWindowSize () {
  return useSyncExternalStore(
    // 订阅 resize 事件
    (callback) => {
      window.addEventListener('resize', callback)
      return () => window.removeEventListener('resize', callback)
    },
    // 获取当前窗口尺寸
    () => ({ width: window.innerWidth, height: window.innerHeight }),
    // SSR 时的默认值
    () => ({ width: 0, height: 0 })
  )
}

function WindowInfo () {
  const { width, height } = useWindowSize()

  return (
    <div>
      窗口尺寸: {width} x {height}
    </div>
  )
}
```

**3. 订阅 LocalStorage**

```tsx
function useLocalStorage (key: string) {
  return useSyncExternalStore(
    // 订阅 storage 事件
    (callback) => {
      window.addEventListener('storage', callback)
      return () => window.removeEventListener('storage', callback)
    },
    // 获取当前值
    () => localStorage.getItem(key),
    // SSR 时返回 null
    () => null
  )
}

function StorageDemo () {
  const theme = useLocalStorage('theme')

  const setTheme = (newTheme: string) => {
    localStorage.setItem('theme', newTheme)
    // 手动触发 storage 事件（同域内不会自动触发）
    window.dispatchEvent(new StorageEvent('storage', {
      key: 'theme',
      newValue: newTheme
    }))
  }

  return (
    <div>
      <p>当前主题: {theme || 'default'}</p>
      <button onClick={() => setTheme('dark')}>设为暗色</button>
      <button onClick={() => setTheme('light')}>设为亮色</button>
    </div>
  )
}
```

**4. 集成第三方状态库**

```tsx
// 与 Redux 集成
function useReduxStore (selector: (state: any) => any) {
  return useSyncExternalStore(
    store.subscribe,
    () => selector(store.getState()),
    () => selector(store.getState()) // SSR
  )
}

// 与 Zustand 集成
function useZustand (store: any, selector: (state: any) => any) {
  return useSyncExternalStore(
    store.subscribe,
    () => selector(store.getState()),
    () => selector(store.getState())
  )
}
```

**为什么需要 useSyncExternalStore**

在 React 18 的并发模式下，渲染可能被中断和恢复，这可能导致外部状态与组件状态不一致。`useSyncExternalStore` 通过以下机制解决这个问题：

* **原子性读取**: 确保状态读取的原子性
* **一致性检查**: 在渲染过程中检查状态是否发生变化
* **自动重渲染**: 状态变化时自动触发重渲染

**与传统方案的对比**

|方案|问题|useSyncExternalStore 的优势|
|---|---|---|
|useEffect + useState|可能出现状态不一致|保证状态一致性|
|直接订阅|并发模式下可能出错|并发安全|
|手动管理订阅|容易出现内存泄漏|自动管理订阅|

**最佳实践**

* **订阅函数稳定性**: 确保 subscribe 函数引用稳定，避免不必要的重新订阅
* **快照函数优化**: getSnapshot 应该返回稳定的引用，相同值应返回相同对象
* **SSR 兼容**: 提供 getServerSnapshot 确保服务端渲染兼容性
* **性能考虑**: 对于高频更新的外部状态，考虑使用防抖或节流

**常见误区**

* **订阅函数不稳定**: 每次渲染都创建新的订阅函数
* **忘记取消订阅**: subscribe 函数必须返回取消订阅的函数
* **快照不稳定**: getSnapshot 返回的值引用不稳定导致过度渲染

:::tip
`useSyncExternalStore` 主要用于库开发者集成外部状态管理。普通业务开发中，优先使用 React 内置的状态管理方案。
:::

* [React 18 新特性](https://react.dev/blog/2022/03/29/react-v18#new-hooks) 官方博客
* [外部状态管理最佳实践](https://github.com/reactwg/react-18/discussions/86) 社区讨论

## useOptimistic 的作用? {#p2-useOptimistic}

<Answer>

`useOptimistic` 是 React 19 引入的一个 Hook，用于实现乐观更新（Optimistic Updates）。它允许在异步操作完成前立即更新 UI，提供更好的用户体验。

**基本语法**

```ts
const [optimisticState, addOptimistic] = useOptimistic(state, updateFn)
```

* `state`: 当前的实际状态
* `updateFn`: 函数，用于生成乐观更新的状态
* `optimisticState`: 乐观更新后的状态
* `addOptimistic`: 触发乐观更新的函数

**核心作用**

|功能|说明|使用场景|
|---|---|---|
|乐观更新|在异步操作前立即更新UI|表单提交、点赞、评论|
|用户体验优化|减少等待时间，提供即时反馈|社交媒体、购物车|
|状态管理|管理临时状态和最终状态|列表增删改、数据同步|

**典型使用场景**

**1. 添加待办事项**

```tsx
import React, { useState, useOptimistic } from 'react'

function TodoApp () {
  const [todos, setTodos] = useState<string[]>(['学习React'])

  const [optimisticTodos, addOptimisticTodo] = useOptimistic(
    todos,
    (state, newTodo: string) => [...state, newTodo + ' (保存中...)']
  )

  const addTodo = async (text: string) => {
    // 立即显示乐观更新
    addOptimisticTodo(text)

    try {
      // 模拟异步操作
      await new Promise(resolve => setTimeout(resolve, 2000))
      // 成功后更新实际状态
      setTodos(prev => [...prev, text])
    } catch (error) {
      // 失败时乐观更新会自动回滚
      console.error('添加失败:', error)
    }
  }

  return (
    <div>
      <button onClick={() => addTodo('新任务')}>添加任务</button>
      <ul>
        {optimisticTodos.map((todo, index) => (
          <li key={index}>{todo}</li>
        ))}
      </ul>
    </div>
  )
}
```

**2. 点赞功能**

```tsx
function LikeButton ({ postId, initialLikes, initialLiked }) {
  const [likes, setLikes] = useState(initialLikes)
  const [liked, setLiked] = useState(initialLiked)

  const [optimisticLikes, addOptimisticLike] = useOptimistic(
    { likes, liked },
    (state, action) => ({
      likes: action.type === 'like' ? state.likes + 1 : state.likes - 1,
      liked: !state.liked
    })
  )

  const handleLike = async () => {
    const action = { type: liked ? 'unlike' : 'like' }
    addOptimisticLike(action)

    try {
      const response = await fetch(`/api/posts/${postId}/like`, {
        method: 'POST',
        body: JSON.stringify(action)
      })
      const data = await response.json()
      setLikes(data.likes)
      setLiked(data.liked)
    } catch (error) {
      console.error('点赞失败:', error)
    }
  }

  return (
    <button onClick={handleLike}>
      {optimisticLikes.liked ? '❤️' : '🤍'} {optimisticLikes.likes}
    </button>
  )
}
```

**3. 购物车更新**

```tsx
function ShoppingCart () {
  const [cart, setCart] = useState([])

  const [optimisticCart, updateOptimisticCart] = useOptimistic(
    cart,
    (state, { type, item }) => {
      switch (type) {
        case 'add':
          return [...state, { ...item, status: 'adding' }]
        case 'remove':
          return state.filter(cartItem => cartItem.id !== item.id)
        default:
          return state
      }
    }
  )

  const addToCart = async (item) => {
    updateOptimisticCart({ type: 'add', item })

    try {
      await fetch('/api/cart/add', {
        method: 'POST',
        body: JSON.stringify(item)
      })
      setCart(prev => [...prev, item])
    } catch (error) {
      console.error('添加到购物车失败:', error)
    }
  }

  return (
    <div>
      {optimisticCart.map(item => (
        <div key={item.id}>
          {item.name} {item.status === 'adding' && '(添加中...)'}
        </div>
      ))}
    </div>
  )
}
```

**工作原理**

* **乐观更新**: 调用 `addOptimistic` 时立即更新 UI
* **自动回滚**: 如果后续状态更新失败，乐观更新会自动回滚
* **状态同步**: 当实际状态更新时，乐观状态会与之同步

**与其他方案的对比**

|方案|优点|缺点|适用场景|
|---|---|---|---|
|useOptimistic|自动回滚、简单易用|需要React 19|新项目、现代应用|
|手动状态管理|兼容性好、控制精细|代码复杂、易出错|复杂业务逻辑|
|第三方库|功能丰富|依赖外部库|大型应用|

**常见误区**

* **过度使用**: 不是所有异步操作都需要乐观更新
* **错误处理**: 忽略异步操作失败的情况
* **状态混乱**: 在复杂场景中乐观状态与实际状态不一致

**最佳实践**

* 仅在用户体验关键的操作中使用乐观更新
* 确保异步操作有适当的错误处理
* 在乐观更新的 UI 中提供明确的视觉反馈

:::tip
乐观更新适合高频交互和网络延迟明显的场景，但要确保异步操作的可靠性和错误处理。
:::

## useId 的作用? {#p3-useId}

<Answer>

`useId` 是 React 18 引入的一个 Hook，用于生成在客户端和服务器端都一致的唯一标识符，主要解决 SSR 中的 hydration 不匹配问题。

**基本语法**

```ts
const id = useId(): string
```

**核心作用**

| 功能 | 说明 | 使用场景 |
|------|------|---------|
| 生成唯一ID | 在客户端和服务端生成一致的唯一标识 | 表单元素、无障碍功能 |
| 避免hydration不匹配 | 确保SSR和CSR中ID的一致性 | 服务端渲染应用 |
| 无障碍性支持 | 为屏幕阅读器等辅助技术提供关联 | `aria-labelledby`、`aria-describedby` |

**典型应用场景**

**1. 表单元素关联**

```tsx
import React, { useId } from 'react'

function LoginForm () {
  const usernameId = useId()
  const passwordId = useId()

  return (
    <form>
      <div>
        <label htmlFor={usernameId}>用户名:</label>
        <input id={usernameId} type="text" />
      </div>
      <div>
        <label htmlFor={passwordId}>密码:</label>
        <input id={passwordId} type="password" />
      </div>
    </form>
  )
}
```

**2. 无障碍功能**

```tsx
function AccessibleComponent () {
  const titleId = useId()
  const descId = useId()

  return (
    <div>
      <h2 id={titleId}>设置面板</h2>
      <p id={descId}>这里是设置面板的详细说明</p>
      <button
        aria-labelledby={titleId}
        aria-describedby={descId}
      >
        保存设置
      </button>
    </div>
  )
}
```

**3. 复杂组件中的多个ID**

```tsx
function SearchComponent () {
  const baseId = useId()

  return (
    <div>
      <label htmlFor={`${baseId}-input`}>搜索:</label>
      <input id={`${baseId}-input`} />
      <button id={`${baseId}-button`}>搜索</button>
      <div id={`${baseId}-results`} role="region" aria-live="polite">
        {/* 搜索结果 */}
      </div>
    </div>
  )
}
```

**SSR 中的重要性**

在服务端渲染中，`useId` 确保了服务器和客户端生成相同的 ID，避免 hydration 不匹配：

```tsx
// ❌ 错误方式 - 可能导致 hydration 不匹配
function BadComponent () {
  const id = Math.random().toString(36)
  return <input id={id} />
}

// ✅ 正确方式 - 使用 useId
function GoodComponent () {
  const id = useId()
  return <input id={id} />
}
```

**注意事项**

* **不要用作 key**: `useId` 不应该用作列表项的 `key` 属性
* **每次调用都是唯一的**: 同一组件中多次调用 `useId` 会返回不同的 ID
* **不要进行字符串拼接**: 避免在 `useId` 结果上进行复杂的字符串操作

**常见误区**

* **误用作 key**: `useId` 不稳定，不适合作为 React 的 key 属性
* **过度使用**: 简单的静态 ID 可能不需要 `useId`
* **服务端渲染理解**: 认为只有客户端渲染才需要 `useId`

:::tip
`useId` 主要用于需要唯一标识符的场景，特别是在 SSR 应用中。对于简单的静态 ID，可以直接使用字符串常量。
:::

## useDebugValue 的作用? {#p3-useDebugValue}

<Answer>

`useDebugValue` 是 React 提供的一个调试专用 Hook，主要用于在 React 开发者工具（React DevTools）中为自定义 Hook 显示调试信息。

**基本语法**

```ts
useDebugValue(value: any, format?: (value: any) => any): void
```

* `value`: 要在开发者工具中显示的值
* `format`: 可选的格式化函数，用于自定义显示格式

**核心作用**

| 功能 | 说明 | 使用场景 |
|------|------|---------|
| 调试信息展示 | 在 React DevTools 中显示自定义 Hook 的状态 | 自定义 Hook 开发 |
| 状态可视化 | 提供更直观的调试体验 | 复杂逻辑调试 |
| 开发环境优化 | 仅在开发环境生效，生产环境会被忽略 | 调试优化 |

**代码示例**

```tsx
import React, { useState, useDebugValue } from 'react'

function useCounter (initialValue: number) {
  const [count, setCount] = useState(initialValue)

  // 基本用法：显示当前状态
  useDebugValue(count)

  // 高级用法：条件显示和格式化
  useDebugValue(count > 10 ? 'High' : 'Low')

  // 使用格式化函数
  useDebugValue(count, value => `Counter: ${value}`)

  const increment = () => setCount(c => c + 1)
  const decrement = () => setCount(c => c - 1)

  return { count, increment, decrement }
}

function useOnlineStatus () {
  const [isOnline, setIsOnline] = useState(navigator.onLine)

  // 显示用户友好的状态信息
  useDebugValue(isOnline ? 'Online' : 'Offline')

  return isOnline
}
```

**使用场景**

* **自定义 Hook 开发**: 为自定义 Hook 提供清晰的调试信息
* **复杂状态管理**: 显示经过计算或转换的状态值
* **条件状态展示**: 根据不同条件显示不同的调试信息
* **团队协作**: 让其他开发者更容易理解 Hook 的当前状态

**性能优化**

```tsx
function useExpensiveHook (data: any[]) {
  const processedData = useMemo(() => expensiveCalculation(data), [data])

  // 延迟格式化，避免不必要的计算
  useDebugValue(processedData, processed =>
    processed ? `${processed.length} items processed` : 'No data'
  )

  return processedData
}
```

**注意事项**

* **仅开发环境**: 生产环境下 `useDebugValue` 不会执行，不会影响性能
* **格式化函数**: 当提供格式化函数时，只有在 DevTools 检查该 Hook 时才会调用
* **使用位置**: 只能在自定义 Hook 内部使用，不能在组件中直接使用

**常见误区**

* **滥用调试**: 不要为每个简单的 Hook 都添加 `useDebugValue`
* **复杂计算**: 避免在 `useDebugValue` 中进行复杂计算，应使用格式化函数
* **生产环境担心**: 无需担心生产环境性能，React 会自动优化

:::tip
`useDebugValue` 主要用于自定义 Hook 的开发和调试阶段。对于简单的 Hook，通常不需要使用；对于复杂的自定义 Hook，合理使用可以大大提升调试效率。
:::

**延伸阅读**

* [useDebugValue](https://react.dev/reference/react/useDebugValue) 官方文档
* [React DevTools](https://react.dev/learn/react-developer-tools) React 开发者工具使用指南
* [Building Your Own Hooks](https://react.dev/learn/reusing-logic-with-custom-hooks) 自定义 Hook 开发指南

</Answer>
