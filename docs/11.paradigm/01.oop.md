# 面向对象

## 什么是面向对象编程（OOP）？它与函数式编程有何区别？{#p1-oop}

<Answer>

1. **OOP 定义**
   面向对象编程（Object-oriented programming OOP）是一种通过对象来封装数据与行为的编程范式。对象是具有状态（数据）和行为（方法）的实体，OOP 的核心思想在于将复杂问题分解为相互作用的对象，从而提高代码的模块化和可维护性。与函数式编程（FP）相比，OOP 更强调状态和可变性，而 FP 强调无副作用的纯函数和不可变数据。

2. **使用方法**
   在 OOP 中，开发者通过定义类（或构造函数）来创建对象，并利用继承、多态和封装来管理代码复杂度。通过对象实例来操作和维护状态。

3. **原理与局限性**
   OOP 通过封装、组合、继承、多态等特性促进代码复用和模块化。但在前端场景中，过度使用继承可能导致组件层级过深，增加维护成本。状态管理不当也容易引发 UI 的非预期变化。

4. **实际应用**
   在前端开发中，OOP 的典型场景如下：
    - **组件化开发**：如 React、Vue 的组件定义等，基于组件模式实现 UI 的封装与复用。
    - **事件系统**：利用发布-订阅模式（观察者模式的一种）实现组件间的解耦和灵活通信。
    - **Express 中间件**：采用了职责链模式，请求在多个中间件中依次处理，每个中间件负责特定的任务。

</Answer>

## 什么是继承，JavaScript 中的继承机制的实现方式？

<Answer>

1. **什么是继承** 继承是面向对象编程中的一种机制，允许一个对象（子类）获取另一个对象（父类）的属性和方法。它使得代码复用成为可能，并且可以通过扩展父类的功能来实现多态。
2. **JavaScript 中的使用原型链实现了继承功能，原型链原理如下**
   1. **构造函数创建**：
      - 当你创建一个构造函数时，例如 `function Person(name) { this.name = name; }`，JavaScript 会自动为 `Person` 函数创建一个 `prototype` 属性，`Person.prototype` 指向一个对象。
      - 默认情况下，`Person.prototype` 对象只有一个 `constructor` 属性，指向 `Person` 函数本身。
   2. **设置原型属性/方法**：
      - 你可以向 `Person.prototype` 对象添加属性和方法，例如 `Person.prototype.sayHello = function() { console.log('Hello, ' + this.name); }`。
      - 这些属性和方法会被所有通过 `Person` 构造函数创建的实例所继承。
   3. **创建实例**：
      - 当你使用 `new Person('Alice')` 创建一个实例时，会发生以下事情：
         - 创建一个新的空对象。
         - 将新对象的 `__proto__` 属性指向 `Person.prototype`。
         - 以新对象为上下文（`this`）调用 `Person` 构造函数，执行构造函数中的代码（例如 `this.name = name`）。
         - 如果构造函数没有显式返回一个对象，则返回新创建的对象。
   4. **属性查找**：
      - 当你访问 `alice.sayHello()` 时，JavaScript 引擎首先检查 `alice` 对象自身是否有 `sayHello` 属性。
      - 如果没有，引擎会查找 `alice.__proto__`，也就是 `Person.prototype`，看它是否有 `sayHello` 属性。
      - 如果找到了，就调用该方法。如果 `Person.prototype` 也没有 `sayHello` 属性，引擎会继续向上查找 `Person.prototype.__proto__`，直到找到该属性或者到达原型链的顶端（`Object.prototype.__proto__` 为 `null`）
   5. **ES6 extens 说明** 在 JavaScript 中，由于没有传统的类继承概念（ES6 引入的 `class` 实际上是语法糖，本质还是基于原型），因此原型链是实现继承的主要方式。
3. **继承的语法**

   | 方法 | 语法示例 | 优势 | 局限性 |
   |---|---|---|---|
   | ES6 `class` 继承 | `class Child extends Parent {}` | 语法简洁，更符合面向对象编程的习惯，支持 super 调用父类方法 | 本质上仍然是原型继承的语法糖，需注意浏览器兼容性 |
   | es5 继承 | `Child.prototype = Object.create(Parent.prototype); Child.prototype.constructor = Child; Parent.call(this, name);` | 结合了原型链继承和构造函数继承的优点，既能继承实例属性，又能继承原型属性 | 父类构造函数会被调用两次，产生不必要的性能开销 |

:::tip
虽然 JS 可以用 `extends class` 模式实现继承，但这个机制的本质还是基于对象的原型链，通过运行时查找确认对象的属性和方法。传统 OOP 语言的继承，比如 C++、JAVA 的**继承特性是编译时确定的而不是运行**时，而 JS 的**继承是运行时动态绑定的**。所以你也可以只通过动态的设置原型链来实现继承。而不需要拘泥于 class 的继承模式。
:::

### 4. 什么是封装？如何在 JavaScript 中实现数据的私有化？

**答案**：

- **背景与意义**  
  封装指将对象的内部状态与行为隐藏起来，仅暴露必要的接口，从而保护数据不被意外修改。它提高了模块的独立性和安全性。

- **使用方法**  
  在 JavaScript 中，可以通过闭包、ES6 私有字段或使用 `WeakMap`/`Symbol` 来实现数据私有化。

- **代码实现**：
  1. **闭包方式**：

     ```javascript
     function Counter () {
       let count = 0 // 私有变量
       return {
         increment () {
           count++
           console.log(count)
         },
         decrement () {
           count--
           console.log(count)
         }
       }
     }
     const counter = Counter()
     counter.increment() // 输出 1
     counter.decrement() // 输出 0
     ```

  2. **ES2022 私有字段**：

     ```javascript
     class CounterClass {
       #count = 0 // 私有字段
       increment () {
         this.#count++
         console.log(this.#count)
       }
     
       decrement () {
         this.#count--
         console.log(this.#count)
       }
     }
     const counterInstance = new CounterClass()
     counterInstance.increment() // 输出 1
     counterInstance.decrement() // 输出 0
     ```

- **局限性与注意事项**  
  闭包实现私有变量时需注意内存管理，ES6 私有字段要求现代浏览器支持。

- **实际应用**  
  常用于设计工具类或库，确保内部状态不被外部直接修改，维护数据完整性。

### 5. 什么是多态？请举例说明在 JavaScript 中如何实现多态行为

**答案**：

- **背景与意义**  
  多态允许一个接口在不同对象中有不同的具体实现，从而提高代码复用性和灵活性。

- **使用方法**  
  在 JavaScript 中，多态常通过继承和方法重写（override）来实现。子类根据需要重写父类方法，调用同一个接口时呈现不同的行为。

- **代码实现**：

  ```javascript
  class Animal {
    speak () {
      console.log('Animal makes a noise.')
    }
  }

  class Dog extends Animal {
    speak () {
      console.log('Dog barks.')
    }
  }

  class Cat extends Animal {
    speak () {
      console.log('Cat meows.')
    }
  }

  function makeAnimalSpeak (animal) {
    animal.speak()
  }

  const dog = new Dog()
  const cat = new Cat()
  
  makeAnimalSpeak(dog) // 输出：Dog barks.
  makeAnimalSpeak(cat) // 输出：Cat meows.
  ```

- **优化与扩展**  
  利用接口统一调用，减少对具体类型的依赖，提高系统扩展性。

- **实际应用**  
  在前端组件中，同一事件接口可以响应不同组件的特定行为，提升系统灵活性和复用性。

### 6. 什么是抽象？JavaScript 如何模拟抽象类或接口？

**答案**：

- **背景与意义**  
  抽象是隐藏具体实现细节，仅暴露核心功能的思想。抽象类或接口定义了行为契约，子类必须实现这些方法，有助于构建统一、可扩展的架构。

- **使用方法**  
  JavaScript 原生不直接支持抽象类/接口，但可通过抛出错误的方式实现。例如，在抽象类中定义必须被重写的方法。

- **代码实现**：

  ```javascript
  class AbstractAnimal {
    constructor () {
      if (new.target === AbstractAnimal) {
        throw new Error('Cannot instantiate abstract class.')
      }
    }
  
    speak () {
      throw new Error('Method "speak()" must be implemented.')
    }
  }

  class Dog extends AbstractAnimal {
    speak () {
      console.log('Dog barks.')
    }
  }

  const dog = new Dog()
  dog.speak() // 输出：Dog barks.
  ```

- **局限性与注意事项**  
  这种方式依赖开发者自觉遵守约定，无法在编译期强制检查。

- **实际应用**  
  适用于团队协作中制定统一接口或抽象契约，确保各模块实现预期行为。

## 🟡 第二阶段：SOLID 设计原则

### 7. 解释 SOLID 原则中的每一项，并讨论其在前端开发中的重要性

**答案**：

SOLID 是面向对象设计的五项基本原则，它们分别为：

- **S (Single Responsibility Principle)**：单一职责原则  
  *背景*：每个模块/类只应负责一种功能。  
  *实际*：使得每个组件或服务职责单一，便于维护和扩展。
- **O (Open/Closed Principle)**：开放封闭原则  
  *背景*：模块对扩展开放，对修改封闭。  
  *实际*：通过继承、接口或组合来扩展功能，而不修改已有代码。
- **L (Liskov Substitution Principle)**：里氏替换原则  
  *背景*：子类对象应能够替换父类对象而不破坏系统行为。  
  *实际*：在组件库中确保继承关系合理，保证组件可替换性。
- **I (Interface Segregation Principle)**：接口隔离原则  
  *背景*：不应强迫客户端依赖它们不使用的方法。  
  *实际*：在前端开发中设计 API 或服务接口时，尽量精简，避免臃肿。
- **D (Dependency Inversion Principle)**：依赖倒置原则  
  *背景*：高层模块不应依赖低层模块，两者都应该依赖于抽象。  
  *实际*：通过依赖注入、接口设计实现模块独立性，提升测试与复用能力。

### 8. 如何在 JavaScript 中实现单一职责原则？请提供示例

**答案**：

- **需求分析**  
  单一职责原则要求每个类或模块只负责一种功能。  
- **设计方案**  
  将原本混合的功能拆分为多个单独模块，每个模块负责一项具体任务。  
- **代码实现**：

  ```javascript
  // 拆分用户认证与日志记录逻辑
  class AuthService {
    login (username, password) {
      // 验证用户信息，返回认证结果
      return username === 'admin' && password === '1234'
    }
  }

  class Logger {
    log (message) {
      console.log('LOG:', message)
    }
  }

  // 前端调用时分别使用不同的服务
  const authService = new AuthService()
  const logger = new Logger()
  
  if (authService.login('admin', '1234')) {
    logger.log('User logged in successfully.')
  }
  ```

- **实际应用**  
  单一职责使得代码更易于维护和测试，各模块之间解耦，项目扩展时也方便添加新功能而不影响现有代码。

### 9. 什么是开放/封闭原则？如何在项目中应用该原则？

**答案**：

- **背景与意义**  
  开放/封闭原则要求软件实体（如类、模块、函数）能够扩展，而不需要修改已存在的代码，以避免引入新的错误。  
- **设计方案**  
  通过使用继承或组合模式扩展现有类的功能，而非直接修改。  
- **代码实现**：

  ```javascript
  // 基础通知类
  class Notifier {
    send (message) {
      console.log(`Sending: ${message}`)
    }
  }
  
  // 扩展：通过继承增加新的发送方式
  class EmailNotifier extends Notifier {
    send (message) {
      // 复用基础逻辑，并扩展邮件发送的细节
      super.send(message)
      console.log(`Sending email with: ${message}`)
    }
  }
  
  const notifier = new EmailNotifier()
  notifier.send('Hello World!')
  ```

- **实际应用**  
  在前端项目中，当新增功能或改变需求时，通过扩展现有模块来保持代码稳定性，并避免引入回归 bug。

### 10. 解释里氏替换原则，并讨论其在组件设计中的应用

**答案**：

- **背景与意义**  
  里氏替换原则要求子类必须能够替换父类，并且程序行为保持不变，保证继承结构中的一致性和可靠性。  
- **使用方法**  
  在组件设计中，确保所有继承自某个组件的子组件都能无缝替换父组件的使用场景，不破坏依赖该接口的逻辑。  
- **实际案例**  
  例如，在设计 UI 库时，父组件定义了统一的接口，子组件（如 Button、Link）必须遵循接口规范，确保渲染与事件处理符合预期。

### 11. 什么是接口隔离原则？在 JavaScript 中如何实现？

**答案**：

- **背景与意义**  
  接口隔离原则要求客户端不应依赖它们不使用的接口，避免构建臃肿的接口。  
- **使用方法**  
  在模块或服务设计时，应将接口拆分为多个小接口，各自关注单一功能，客户端仅依赖自身需要的那部分接口。  
- **代码实现**：

  ```javascript
  // 定义小接口：读操作接口和写操作接口
  class Reader {
    read () {
      // 读取数据
    }
  }

  class Writer {
    write (data) {
      // 写入数据
    }
  }

  // 客户端可以按需组合
  class FileManager extends Reader {
    constructor (writer) {
      super()
      this.writer = writer
    }
  
    save (data) {
      this.writer.write(data)
    }
  }
  ```

- **实际应用**  
  接口隔离提高了系统的灵活性，前端 API 设计时常将不同操作拆分，避免让组件承担过多职责。

### 12. 解释依赖倒置原则，并讨论其在模块化开发中的作用

**答案**：

- **背景与意义**  
  依赖倒置原则要求高层模块不依赖于低层模块，而应依赖于抽象，这样可以降低模块之间的耦合度。  
- **使用方法**  
  通过抽象接口和依赖注入（Dependency Injection）使高层模块在运行时获得所需功能，而非硬编码具体实现。  
- **代码实现**：

  ```javascript
  // 抽象接口
  class Service {
    execute () {
      throw new Error('Method not implemented.')
    }
  }

  // 具体实现
  class ApiService extends Service {
    execute () {
      console.log('Calling API...')
    }
  }

  // 高层模块通过依赖注入使用抽象接口
  class Controller {
    constructor (service) {
      this.service = service
    }
  
    handleRequest () {
      this.service.execute()
    }
  }

  const serviceInstance = new ApiService()
  const controller = new Controller(serviceInstance)
  controller.handleRequest() // 输出：Calling API...
  ```

- **实际应用**  
  前端模块化开发中常采用依赖注入框架或设计模式，使各模块独立开发和测试，便于维护和扩展。

### 14. 解释以下创建型模式，并提供 JavaScript 实现示例：单例模式、工厂模式、抽象工厂模式

**答案**：

- **单例模式**  
  - **背景**：确保系统中某个类只有一个实例，提供全局访问点。  
  - **代码实现**：

    ```javascript
    class Singleton {
      constructor () {
        if (Singleton.instance) {
          return Singleton.instance
        }
        this.timestamp = new Date()
        Singleton.instance = this
      }
    
      getTime () {
        return this.timestamp
      }
    }
    
    const s1 = new Singleton()
    const s2 = new Singleton()
    console.log(s1 === s2) // true
    ```

- **工厂模式**  
  - **背景**：通过工厂方法创建对象，隐藏对象创建的具体实现。  
  - **代码实现**：

    ```javascript
    class Car {
      constructor (model) {
        this.model = model
      }
    }

    class CarFactory {
      createCar (model) {
        return new Car(model)
      }
    }

    const factory = new CarFactory()
    const car = factory.createCar('Tesla Model 3')
    console.log(car.model) // Tesla Model 3
    ```

### 16. 解释以下行为型模式，并提供 JavaScript 实现示例：观察者模式、策略模式、命令模式、状态模式

  - **背景**：当对象状态改变时，自动通知依赖其的所有对象。

    ```javascript
    class Subject {

      }

        this.observers.push(observer)
      }
    
      unsubscribe (observer) {
        this.observers = this.observers.filter(obs => obs !== observer)
      }

        this.observers.forEach(observer => observer.update(data))
      }

      update (data) {
        console.log('Observer received:', data)
      }
    }

    const observer1 = new Observer()
    ```

- **设计方案**

  ```javascript
    isNonEmpty: value => value !== '',
    isEmail: value => /\S+@\S+\.\S+/.test(value),
    isNumber: value => !isNaN(value)
  }
  
  // 表单验证器
  class Validator {
    constructor () {
      this.cache = []
    }
  
    add (field, rules) {

            return rule.errorMsg
          }
        })
      })
    }
  
    start () {
      for (const validate of this.cache) {
        const errorMsg = validate()
        if (errorMsg) return errorMsg
      }
      return null
    }
  }

  validator.add(formField, [
    { strategy: 'isNonEmpty', errorMsg: 'Field is required.' },
    { strategy: 'isEmail', errorMsg: 'Invalid email format.' }
  ])
  
  const result = validator.start()
  console.log(result) // 如果验证通过返回 null，否则返回错误信息
  ```

### 26. 实现一个事件总线系统，使用观察者模式管理事件订阅与发布

**答案**：

- **需求分析**  
  事件总线需要集中管理应用中各组件间的事件通信，支持订阅、取消订阅和发布。  
- **代码实现**：

  ```javascript
  class EventBus {
    constructor () {
      this.events = {}
    }
  
    // 订阅事件
    subscribe (event, callback) {
      if (!this.events[event]) {
        this.events[event] = []
      }
      this.events[event].push(callback)
    }
  
    // 发布事件
    publish (event, data) {
      if (this.events[event]) {
        this.events[event].forEach(callback => callback(data))
      }
    }
  
    // 取消订阅
    unsubscribe (event, callback) {
      if (this.events[event]) {
        this.events[event] = this.events[event].filter(cb => cb !== callback)
      }
    }
  }

  // 使用示例
  const eventBus = new EventBus()
  const handler = data => console.log('Event received:', data)
  eventBus.subscribe('dataUpdate', handler)
  eventBus.publish('dataUpdate', { key: 'value' }) // 输出：Event received: { key: 'value' }
  ```

- **实际应用**  
  前端框架或大型应用中常采用事件总线管理组件之间的通信，提高解耦性。
