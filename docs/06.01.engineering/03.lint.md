# lint

## eslint 是如何工作的？{#p1-eslint}‘

<Answer>

1. **加载配置** 通过 [loadConfigFile](https://github.com/eslint/eslint/blob/6c074206ae0eae4816197a57648b415832a20e1d/lib/config/config-loader.js#L199C16-L199C30) 加载配置, 配置规则详见 [config file](https://eslint.org/docs/latest/use/configure/configuration-files)
2. **解析 AST** 默认采用 [espree](https://github.com/eslint/js/tree/main/packages/espree). AST 规则遵循 [ESTree](https://github.com/estree/estree), ESLint 也支持 markdown/css 等解析，参考 [markdown 解析](https://eslint.org/blog/2024/10/eslint-json-markdown-support/),  可以通过 [eslint explorer](https://explorer.eslint.org/) 查看不同 AST
3. **Rule** 遍历节点按规则检查，每条规则接收上下文（RuleContext），在特定 AST 节点上报告问题并可返回 fixer（基于 SourceCode）生成补丁
4. **生成报告**
5. **格式化** 按规则提供 fixer 自动修复

</Answer>

## eslint 如何实现增量 lint?{#p1-patch-eslint}

<Answer>

1. 结合 git diff 与 eslint，只对 MR/PR/commit 变更文件 lint

   ```bash
   # 方案1：命令行增量 lint（仅校验 master 分支与当前分支变更的 js 文件）
   git diff --name-only --diff-filter=d master | grep '\.js$' | xargs eslint
   ```

2. lint-staged + husky（pre-commit 钩子自动 lint 暂存文件） `npm install lint-staged husky --save-dev`

   ```json
   {
      "husky": {
         "hooks": {
            "pre-commit": "lint-staged"
         }
      },
      "lint-staged": {
         "*.js": ["eslint --fix", "git add"]
      }
   }
   ```

**延伸阅读**

* [lint-staged](https://github.com/okonet/lint-staged) — 暂存文件 lint 工具
* [husky](https://github.com/typicode/husky) — git 钩子管理工具
* [ESLint CLI](https://eslint.org/docs/latest/use/command-line-interface) — 命令行用法
* [Git diff-filter](https://git-scm.com/docs/git-diff#Documentation/git-diff.txt---diff-filterACDMRTUXB) — 文件过滤参数说明

</Answer>
