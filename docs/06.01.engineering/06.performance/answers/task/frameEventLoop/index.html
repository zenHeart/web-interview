Frame 是否有独立事件循环？

结论（浏览器模型）：同一 浏览上下文组(Browsing Context Group) 中的每个 iframe（同源或跨源）通常运行在 各自的 JavaScript 执行上下文 内，但是否拥有 独立线程/事件循环 取决于浏览器的进程/线程调度策略：

  • 同源 iframe（多数情况）：与父页面共享同一渲染进程与任务调度序列；脚本执行互相抢占一个主线程（复用事件循环队列集合）。
  • 跨源 iframe：可能被浏览器放入不同的渲染进程（站点隔离策略），拥有独立的任务队列集合，但仍遵循同一事件循环规范；不可直接访问彼此 DOM。
  • Chrome Site Isolation 下：跨站点 iframe 更倾向运行在不同进程，因此宏/微任务调度彼此独立；但这属于实现层优化，不改变 Web 可见语义。

  • 跨站点（若改为跨域 src）时，有可能看到 iframe 的任务序列与父页面脱钩（不同进程），但网络/进程切换引入调度差异。
    • 
    
  • 规范角度：事件循环模型统一；实现角度：浏览器可多进程/多线程分隔不同 frame，提高稳定性与隔离。

面试总结用语示例

  
一个 iframe 不必“创建新的标准事件循环规范”，而是浏览器实现可以为其分配独立的渲染进程与任务队列集合；同源大概率复用同一个进程与主线程，脚本互相阻塞；跨站点出于安全与稳定性可能拆分进程。判断复用还是独立，应从“站点隔离策略 + 任务调度表现”而非假设每个 frame 都固定独立。
