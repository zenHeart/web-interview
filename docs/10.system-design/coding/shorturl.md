
# 如何设计短链系统？ {#P1-short-url}

<Answer>

**核心概念/解决方案:**

- 编码与唯一性：Base62/自增/雪花 ID；冲突检测与重试；可读性与长度
- 存储与缓存：KV 主存储（MySQL/Redis/LSM）+ 热点缓存；热点/过期淘汰
- 跳转与观测：HTTP 30x、埋点与防滥用（限流/验证码/黑名单）
- 运营能力：短链过期/禁用、批量/自定义别名、多租户隔离

### 核心功能

1. **URL转换**
   - 长URL到短URL的映射
   - 短URL到长URL的重定向

2. **技术方案**
   - Base62编码
   - 分布式ID生成
   - Redis缓存热门URL

3. **数据持久化**
   - 主从复制
   - 定期备份

#### 可能的追问

1. 如何处理冲突？
2. 如何提高系统可用性？
3. 如何处理过期链接？
4. 如何防止滥用？

**面试官视角:**

- 关注短链冲突/热点与一致性；防刷/风控与多租户；回收/过期策略

**延伸阅读:**

- Twitter Snowflake、Redis HyperLogLog/布隆过滤器
