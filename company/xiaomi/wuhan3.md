## 题库

### P0 核心必考题

#### 1. 单链表原地反转（迭代与递归实现及防断链核心推导）？ {#p0-reverse-linked-list}

<Answer>
**核心结论**：
单链表反转（**LeetCode 206. 反转链表**）是数据结构中最经典也是考察频率最高的算法题。其核心难点在于：在修改节点指针指向时，原链表的下一个节点引用会丢失（断链）。解题关键是在修改 `curr.next` 之前，必须使用临时变量 `nextTemp` 提前保留后继节点引用。**双指针迭代法空间复杂度为 $O(1)$，时间复杂度为 $O(N)$，为生产环境最优解**。

**原理解析与双指针迭代推导**：
1. 维护两个指针：`prev`（初始化为 `null`）与 `curr`（初始化为 `head`）。
2. 循环遍历链表直至 `curr === null`：
   - 暂存后继：`const nextTemp = curr.next;`
   - 反转指向：`curr.next = prev;`
   - 双双步进：`prev = curr; curr = nextTemp;`
3. 循环结束时，`prev` 恰好指向原链表的最后一个节点，即新链表的头节点，直接返回 `prev`。

**标准代码手写**：
```typescript
class ListNode {
  val: number;
  next: ListNode | null = null;
  constructor(val?: number, next?: ListNode | null) {
    this.val = val === undefined ? 0 : val;
    this.next = next === undefined ? null : next;
  }
}

// 1. 双指针迭代法 (最优解，推荐面试书写)
function reverseListIterative(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null;
  let curr = head;

  while (curr !== null) {
    const nextTemp: ListNode | null = curr.next; // 1. 暂存后继节点防止断链
    curr.next = prev;                            // 2. 反转当前节点指针
    prev = curr;                                 // 3. 前驱指针前移
    curr = nextTemp;                             // 4. 当前指针前移
  }

  return prev;
}

// 2. 递归法 (辅助拓展)
function reverseListRecursive(head: ListNode | null): ListNode | null {
  if (head === null || head.next === null) {
    return head;
  }

  const newHead = reverseListRecursive(head.next);
  head.next.next = head; // 让后继节点指向自己
  head.next = null;      // 断开原正向引用防止成环

  return newHead;
}
```

**面试官视角**：
- 考核候选人指针操作的熟练度与边界情况考量（空链表、单节点链表）。
- 延伸追问：“如何实现链表内指定区间 $[m, n]$ 的局部反转（LeetCode 92）？”
- 答：“使用虚拟头节点（Dummy Head）定位到第 $m-1$ 个节点，采用头插法将区间内的节点依次前置插入。”
</Answer>

#### 2. 企业数字化中台复杂审批流动态节点校验与 BPMN 流程编排引擎设计？ {#p0-bpmn-approval-workflow}

<Answer>
**核心结论**：
在企业中台 ERP/OA 体系中，业务审批流包含串行审批、并行网关（会签/或签）、排他网关（条件分支路由）与驳回重申。前端可视化编排引擎采用**图形图元数据模型（Graph Model: Nodes & Edges）+ 状态机执行器（FSM）+ 动态表达式求值（Expression Evaluator）**架构。节点间通过唯一的流转事件驱动，确保在复杂分支与并行合并时能够精准校验流程合法性与合规死锁。

**原理解析与架构设计**：
1. **数据模型（JSON / XML Schema）**：
   - 流程定义抽象为有向图结构，包含 `startNode`、`userTask`（审批节点）、`exclusiveGateway`（分支路由）、`parallelGateway`（并行会签）与 `endNode`。
   - 边（Edge）附带条件表达式（例如：`${amount > 50000 && department === 'IT'}`）。
2. **合法性与死锁静态校验**：
   - 流程发布前必须执行图遍历算法：
     1. **孤立节点检测**：除起止节点外，所有节点入度与出度必须 $\ge 1$；
     2. **环路死锁检测**：使用 DFS 深度优先遍历配合染色算法排查非预期的死循环依赖；
     3. **可达性验证**：从开始节点出发必须能够保证存在至少一条有效路径直达结束节点。
3. **动态条件求值**：
   - 在前端表单填写时，输入数据实时推入流程引擎沙箱，解析网关出边条件，在 UI 上实时高亮预测后续将要流转的审批人，提升审批透明度。

**面试官视角**：
- 考核候选人对大型企业级复杂业务的建模与系统架构抽象功底，是否具备平台型产品的设计能力。
</Answer>

### P1 高频必会题

#### 1. 万级行数、多维度动态合并单元格的 Web 表格高性能渲染方案？ {#p1-dynamic-table-merge-rendering}

<Answer>
**核心结论**：
在供应链财务对账场景中，表格数据动辄数万行，且存在多列跨行跨列合并（`rowspan` / `colspan`）。若使用原生 `<table>` 渲染全部 DOM，极易导致浏览器假死。解决方案是采用**二维虚拟滚动（2D Virtual Scroll）+ 预编译合并区间映射树（Merge Map）**：在数据加载后预先计算合并单元格的绝对起始与跨越坐标，渲染视口时，只要合并区域与视口相交，就动态扩展渲染该合并单元格并在视口边缘执行吸顶锚定，兼顾极致流畅度与复杂合并展示。

**面试官视角**：
- 考察点：是否经历过大中型企业数字化系统的高难性能攻坚，能否驾驭复杂的几何计算与虚拟滚动算法。
</Answer>
