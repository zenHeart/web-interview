一之二、真题信源层级（Interview Evidence, 2026 起为一级输入）​

为什么单列：2026-10 的全库遍历发现，公开克隆的题库仓内容普遍滞后且 AI 方向为零（pro-collection/interview-question 最新一期 2025-09；front-end-interview-handbook 是唯一仍活跃且含 AI 面经的仓，最后更新 2026-10-05）。因此「最新真题」这一层不能只靠 L2 仓库，必须引入按时间排序的一线面经源。

层级信源性质采集方式已知局限
Ecareers/resume/2026/jobs/agents/mianjing.json（385 条真实面经题，含公司/岗位/出现次数）本机一手快照，2026-09 取自牛客随 careers 仓更新只覆盖 AI Agent 方向；不含前端方向
L2牛客面经帖（nowcoder.com/discuss/*、/feed/main/detail/*）一线真实面试记录，2026-09/10 仍高频更新只读抓取公开页，抽取 desc/content 字段部分帖正文仅登录可见；desc 为预览，长文需换字段抓
L2repos/front-end-interview-handbook/（yangshun）含 OpenAI / Harvey / Canva / Microsoft / Discord 轮次真题本地浅克隆公司向题面偏英文教材体，需改写为中文口吻
L2repos/interview-question/（pro-collection）带热度与出题公司标注的连续期真题本地浅克隆最新 2025-09；AI 方向为零
L3各类题单聚合站（careerstack / ai-interview-guide 等）广角线索仅用于发现线索只作线索，不作事实源；发布主体与题面真实性不可核实

真题采集的证据纪律：

  1. 题目进入题库前，必须能在上述某一源里定位到原文出处（URL 或 repos/ 相对路径 + 行号）；
  2. 同一主题若只有 L3 摘要支撑，不得作为真题录入；
  3. 「某题在多家公司反复出现」这类频次结论，必须能引用到具体计数来源（如 mianjing.json 的 count 字段）。

ASR 转写指标 WERWER = (S + D + I) / N = (S + D + I) / (S + D + C)，其中 S 替换、D 删除、I 插入、C 正确、N 参考词数；由词级 Levenshtein 距离（动态规划对齐）导出，0 为完美。官方指标卡明写：这类度量不提供错误性质的任何细节。因此 WER 对错误位置不敏感、分母随样本长度变化，只能用于同口径的引擎版本对比与回归门禁，不能当业务验收指标；中文等无空格语言因缺词边界更常用 CER，报数必须声明口径"WER 降低必然意味着体验变好" / 把 WER 当业务验收指标 / 不声明中文是词级还是字级口径 / 忽略 D（删除）类错误反映的是端点检测切早huggingface.co/spaces/evaluate-metric/wer

Agent Skills 规范官方规范（agentskills.io）：Skill 是含 SKILL.md 的目录，通过渐进式披露（progressive disclosure）三段加载——Discovery（启动只加载 name + description）→ Activation（匹配后读入完整 SKILL.md）→ Execution；description 承担全部触发责任，规范对 description 有 1024 字符硬上限。官方触发评测口径：约 20 条查询（810 条 should-trigger + 810 条 should-not-trigger），负例须为近似命中（near-miss）；每条跑多次（官方建议 3 次）取 trigger rate，阈值起点 0.5；并需 train / validation 划分防止对着评测集过拟合。官方同时指出：Agent 通常只对"超出自身能力范围"的任务考虑 skill，简单请求不触发属正常"Skill 路由有一个专门的路由函数" / 用明显无关的负例充数 / 跑一次就判定通过 / 把"触发准确率"与"输出质量"混为一谈agentskills.io/home、/skill-creation/optimizing-descriptions、/specification
Prompt 压缩LLMLingua = arXiv:2310.05736（2023-10-09，Jiang Huiqiang 等，《LLMLingua: Compressing Prompts for Accelerated Inference of Large Language Models》）：由粗到细的 prompt 压缩，含预算控制器（保语义完整性）、token 级迭代压缩、基于指令微调的分布对齐，论文报告最高 20 倍压缩、性能损失很小（官方数字）。压缩是独立于生成的研究问题，常用比主模型更小的专用模型承担"压缩就是截断前 N 个 token" / "压缩一定用大模型才靠谱" / 把 20x 当作通用结论arxiv.org/abs/2310.05736
RLHF / 对齐训练InstructGPT = arXiv:2203.02155（2022-03-04，Ouyang Long 等，《Training language models to follow instructions with human feedback》）：三段式 = SFT（人工示范）→ 奖励模型 RM（对同一 prompt 的多个候选做排序，非绝对打分）→ PPO 策略优化；目标函数含对 SFT 策略的 KL 惩罚（防奖励黑客 / 跑偏）；论文摘要明确写「1.3B 参数的 InstructGPT 输出被人类偏好胜过 175B 的 GPT-3，尽管参数少 100 倍」——这是论文自己的结论，须写「论文报告」。DPO = arXiv:2305.18290（2023-05-29，Rafailov Rafael 等）：直接用偏好数据优化策略，不训练独立 RM、不需要显式 RL 循环。OpenAI 另有 RFT（reinforcement fine-tuning）：官方文档写明它「relies on a programmable grader that scores every candidate response」，与人工偏好对齐是两条不同路线"ChatGPT 就是拿 RL 训了下模型" / "RLHF 直接用人类打分当 reward" / "DPO 就是 DPO 论文里的 DPO"（DPO 是 2023 年论文，不是 RLHF 同义词） / 把 1.3B 胜过 175B 说成「小模型已经超过大模型」arxiv.org/abs/2203.02155、arxiv.org/abs/2305.18290、platform.openai.com/docs/guides/reinforcement-fine-tuning
Agent 记忆分层（学术口径）CoALA = arXiv:2309.02427（2023-09-05，Sumers Theodore R. 等，《Cognitive Architectures for Language Agents》）：把 Agent 记忆拆为工作记忆（working memory） + 长期记忆三分（语义 semantic / 情节 episodic / 程序 procedural），语义记忆存世界事实、情节记忆存行为序列。MemGPT = arXiv:2310.08560（2023-10-12，Packer Charles 等，《MemGPT: Towards LLMs as Operating Systems》）：提出 virtual context management，借操作系统分层内存（快慢存储间搬运数据）的思路管理不同 memory tiers，用 interrupts 管理控制流"CoALA 的分类是短期 / 长期两分" / "MemGPT 就是给 LLM 加个长期记忆库" / 把会话级 / 任务级 / 项目级说成是论文里的原始术语（那是本库面向工程的分层，论文是认知科学口径）arxiv.org/abs/2309.02427、arxiv.org/abs/2310.08560
Agent 链路性能与可观测性（官方口径与链接漂移）OpenAI 延迟优化指南 = platform.openai.com/docs/guides/latency-optimization；Anthropic Prompt Caching 文档 = docs.anthropic.com/en/docs/build-with-claude/prompt-caching（文档载明 5m / 1h 两种缓存 TTL）；OpenTelemetry GenAI 语义约定已迁出主仓 → 现址为 github.com/open-telemetry/semantic-conventions-genai（覆盖 GenAI spans / metrics / events，并含 MCP 约定）；vLLM 指标文档现址 = docs.vllm.ai/en/latest/usage/metrics.html（旧路径 serving/metrics.html 已 404）"OTel GenAI 语义约定在 opentelemetry.io/docs/specs/semconv/gen-ai/"（该页现为 Moved 空壳页，只提示已迁移） / "vLLM 指标在 serving/metrics"（已 404） / 把 Anthropic 的 prompt cache TTL 说成只有 5 分钟（文档同时提供 1 小时）opentelemetry.io 的 gen-ai 页 + github.com/open-telemetry/semantic-conventions-genai、docs.vllm.ai/en/latest/usage/metrics.html
采样参数与复读机Hugging Face 官方生成参数中 repetition_penalty 默认 1.0 表示不惩罚（需显式调大才有约束力）；no_repeat_ngram_size 是硬性禁止 n-gram 重复，会破坏代码、JSON、报文等合法重复；encoder_repetition_penalty 只惩罚输入中未出现的序列"默认就开着重复惩罚" / "no_repeat_ngram_size 应该常开" / 把复读归因于"模型能力不足"（复读是解码阶段退化）huggingface.co/docs/transformers/main/en/main_classes/text_generation
注意力变体与 KV CacheGQA = arXiv:2305.13245（2023-05-22，Ainslie 等）：MQA 只用单个 KV head，GQA 用介于 1 与 query head 数之间的 KV head 数；MHA checkpoint 可用约 5% 预训练算力 uptraining 成 MQA/GQA。Llama 2 = arXiv:2307.09288（2023-07-18）Table 1 有专门一列标 GQA：34B 与 70B 用 GQA，7B 与 13B 不用（原文写明是为 improved inference scalability）。Mixtral 8x7B 的 config.json 是可机读实证：num_attention_heads = 32、num_key_value_heads = 8（G=4）。KV Cache 体积只与 KV head 数成正比，与 query head 数无关"GQA 减少了参数量"（一个参数都没减）/ "MQA 无损"（论文明确说可能质量退化）/ "省下 KV Cache 就是省计算量"（decode 是 memory-bound，但计算量基本没变）/ "Llama 2 全系都用 GQA"arxiv.org/abs/2305.13245、arxiv.org/abs/2307.09288、huggingface.co/mistralai/Mixtral-8x7B-v0.1 的 config.json
混合专家模型 MoEMixtral 8x7B = arXiv:2401.04088（2024-01-08）：架构同 Mistral 7B，差别是每层 8 个前馈块（即专家），router 为每个 token、每层选出 2 个专家并合并输出；总 46.7B，每 token 仅激活 13B，上下文 32k。其 config.json：num_local_experts = 8、num_experts_per_tok = 2。DeepSeek-V3 = arXiv:2412.19437（2024-12-27）：671B 总参、每 token 激活 37B；论文原文写明每个 MoE 层由 1 个共享专家 + 256 个路由专家组成，路由专家中每 token 激活 8 个；采用 auxiliary-loss-free 负载均衡。MoE 省的是推理算力，不省显存（全部专家权重仍要驻留）"MoE 减少了参数量" / "MoE 省显存" / "Mixtral 每 token 激活 8 个专家" / "DeepSeek-V3 激活 256 个专家" / 把 DeepSeek-V3 的 256 说成激活数arxiv.org/abs/2401.04088、arxiv.org/abs/2412.19437、huggingface.co/mistralai/Mixtral-8x7B-v0.1 的 config.json
Scaling LawKaplan et al. = arXiv:2001.08361（2020-01-23，《Scaling Laws for Neural Language Models》）：损失随模型规模 N、训练数据量 D、算力 C 呈幂律下降。Chinchilla / Hoffmann et al. = arXiv:2203.15556（2022-03-29）：训练了400 个语言模型（70M 到 160 亿以上参数、50 亿到 5000 亿 token），结论是 compute-optimal 训练时模型大小与训练 token 数应等比例扩展（模型翻倍则 token 也翻倍），此前的模型普遍欠训练；同算力预算的 Chinchilla（70B） 显著胜过 Gopher（280B）。这是经验规律不是定理；「小模型过量训练」是业界工程实践，不是定律本身"参数越多一定越好" / "数据越多越好"（原文是固定算力下的配比结论）/ "Scaling Law 是定理" / 把 Kaplan 与 Chinchilla 的年份写反 / 把「算力最优」与「效果最优」混为一谈arxiv.org/abs/2001.08361、arxiv.org/abs/2203.15556
投机解码Leviathan et al. = arXiv:2211.17192（2022-11-30，《Fast Inference from Transformers via Speculative Decoding》）：小模型 q 连续提议 γ 个 token，target p 一次前向并行验证，以概率 min(1, p(x)/q(x)) 逐个接受；某位被拒时从归一化的 (p - q) 正部分布补采一个并截断 —— 这正是「输出分布与只用 target 完全一致（lossless）」的来源。论文式 (1)：一次 target 调用产出的期望 token 数 = (1 - α^(γ+1)) / (1 - α)；定理 3.5：单步接受率 β = 1 - D_LK(p, q)，而 D_LK 正是 p 与 q 的总变差距离，即接受率 = 1 - 总变差距离。对比：Blockwise Parallel Decoding 等近似方法只支持贪心解码且只保下游质量，投机解码保的是分布一致"小模型生成、大模型润色"（那是有损的）/ "输出和原来一模一样"（不变的是分布，不是逐 token 序列）/ "和量化是一回事" / "draft 越大越好" / 把投机解码说成提升总吞吐（它降的是单请求时延，与连续批处理是不同维度）arxiv.org/abs/2211.17192（正文 3.1 节与定理 3.5）
GraphRAG官方文档 microsoft.github.io/graphrag：索引四阶段 = Graph Extraction → Graph Augmentation（层次化 Leiden 社区检测，递归聚类直到社区规模阈值）→ Community Summarization（每个社区一份 Community Report）→ Text Embedding；Query Engine 提供 Local / Global / DRIFT / Basic Search / Question Generation 五类查询。Global Search 官方原文是「searching over all AI-generated community reports in a map-reduce fashion」，且自述「a resource-intensive method」，适合需要理解整个数据集整体的问题；Local Search 以抽取实体为种子，经 entity-text unit / entity-report / entity-entity relationship / entity-covariate 四类映射召回候选后统一排序过滤"GraphRAG 是更准的向量检索"（它是另一套索引）/ "GraphRAG 查询更快"（索引更贵、查询更贵）/ 把它与「知识图谱问答」混为一谈 / 说图索引省了 LLM 成本（建图反而更耗 LLM）microsoft.github.io/graphrag/index/default_dataflow/、/query/overview/、/query/local_search/
提示注入间接提示注入 = arXiv:2302.12173（2023-02-23，Greshake 等，《Not what you've signed up for: Compromising Real-World LLM-Integrated Applications with Indirect Prompt Injection》）：攻击者无需接触你的界面，只需把恶意指令埋进会被检索到的数据（网页、邮件、文档、工具返回值）；根因是 LLM 集成应用把数据与指令混在同一 token 流里；论文结论是没有彻底解法，必须纵深防御（架构层权限边界、输入侧标记、输出侧不执行、专用检测模型）"加个安全过滤就防住了" / "只有用户直接输入才会触发" / 把提示词层面的加固当成唯一防线 / 把间接注入与越狱（jailbreak）混为一谈 / 把「模型只产出意图、代码判合法性」说成提示词技巧arxiv.org/abs/2302.12173、owasp.org 的 LLM01 条目
ReflexionShinn et al. = arXiv:2303.11366（2023-03-20，《Reflexion: Language Agents with Verbal Reinforcement Learning》）：不更新任何权重，靠自然语言反思写入 episodic memory buffer，下一轮重试时把该反思带进上下文；三角色 = Actor（执行）/ Evaluator（给反馈）/ Self-Reflection（把反馈转成可复用的语言化经验）；反馈信号可为标量或自由文本，来源可外部或内部模拟"Reflexion 是少样本学习的变体" / "反思就是让模型再想一遍" / "它和 PPO 是两种 RL 算法" / 把 Reflexion 与外部多 Agent 辩论混为一谈 / 忽略「错误反思会被固化」这个风险arxiv.org/abs/2303.11366

「规范定稿 / Chrome 推出 / Baseline」三者不可互相替代——这是本库最容易写出自相矛盾答案的地方。典型反例：Anchor Positioning 的 anchor() 在 Chrome 125 已有，但整体 Baseline = false；View Transitions 已是 Baseline low，但 Firefox 至今没有 @view-transition 规则。
