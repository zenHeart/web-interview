一之二、真题信源层级（Interview Evidence, 2026 起为一级输入）​

为什么单列：2026-10 的全库遍历发现，公开克隆的题库仓内容普遍滞后且 AI 方向为零（pro-collection/interview-question 最新一期 2025-09；front-end-interview-handbook 是唯一仍活跃且含 AI 面经的仓，最后更新 2026-10-05）。因此「最新真题」这一层不能只靠 L2 仓库，必须引入按时间排序的一线面经源。

真题采集的证据纪律：

  1. 题目进入题库前，必须能在上述某一源里定位到原文出处（URL 或 repos/ 相对路径 + 行号）；
  2. 同一主题若只有 L3 摘要支撑，不得作为真题录入；
  3. 「某题在多家公司反复出现」这类频次结论，必须能引用到具体计数来源（如 mianjing.json 的 count 字段）。

ASR 转写指标 WERWER = (S + D + I) / N = (S + D + I) / (S + D + C)，其中 S 替换、D 删除、I 插入、C 正确、N 参考词数；由词级 Levenshtein 距离（动态规划对齐）导出，0 为完美。官方指标卡明写：这类度量不提供错误性质的任何细节。因此 WER 对错误位置不敏感、分母随样本长度变化，只能用于同口径的引擎版本对比与回归门禁，不能当业务验收指标；中文等无空格语言因缺词边界更常用 CER，报数必须声明口径"WER 降低必然意味着体验变好" / 把 WER 当业务验收指标 / 不声明中文是词级还是字级口径 / 忽略 D（删除）类错误反映的是端点检测切早huggingface.co/spaces/evaluate-metric/wer

AI 应用可观测性与 GenAI 语义约定OpenTelemetry GenAI 语义约定已从主语义约定仓迁出为独立仓 open-telemetry/semantic-conventions-genai（2026-10-29 仍在更新）。核心属性 gen_ai.operation.name 取值 chat / embeddings / execute_tool / generate_content / invoke_agent；Agent 侧另有 create_agent / invoke_agent / execute_tool 三类 span；属性含 gen_ai.request.model、gen_ai.response.model、gen_ai.response.finish_reasons、gen_ai.agent.*，记忆侧含 gen_ai.memory.*，token 用量见 gen_ai.client.token.usage。仓内已覆盖 MCP（mcp.md）与 A2A（a2a.md），即模型调用 / 工具协议调用 / Agent 间调用可落在同一棵 trace 树。厂商无关（OpenAI、Anthropic、AWS Bedrock、Azure AI Inference 各一页）"GenAI 语义约定是 OpenAI 专有的" / "装个通用 APM 插件就满足 AI 可观测性"（只会记 HTTP，看不到决策链）/ "有 trace 就能复现"（缺 State 快照与入参快照，只能知道做了什么、不知道看到了什么）/ 把可观测性与评测混为一谈github.com/open-telemetry/semantic-conventions-genai、opentelemetry.io/docs/specs/semconv/gen-ai/
Embedding 字段分工与向量库过滤语义字段进 embedding、数值与枚举字段做结构化 filter——余弦相似度表达不了数值大小关系（价格写成「¥299」与「¥2999」在语义上近乎同义），且数字 token 会稀释语义信号。post-filter 陷阱（pgvector 官方 README 口径）：近似索引（HNSW / IVFFlat）上 WHERE 过滤在索引扫描之后施加，过滤命中约 10% 的行、且用默认 hnsw.ef_search = 40 时，平均只有约 4 行能通过过滤，且不报错；修法是过滤列建索引 + 开启迭代索引扫描（iterative index scans，pgvector 0.8.0 起提供，hnsw.max_scan_tuples / ivfflat.max_probes 兜最坏耗时），过滤值种类少用部分索引、种类多用分区。MTEB = arXiv:2210.07316（2022-10-13），只适合作初筛，选型必须自建带真实 query 的域内小评测集"把所有字段拼起来 embed 才不丢信息" / "加了 filter 结果数就不受影响"（近似索引下会静默变少）/ "HNSW 比 IVFFlat 全面更快"（pgvector 官方口径：HNSW 查询更优但建索引更慢更吃内存，IVFFlat 反之）/ 把 MTEB 当选型结论github.com/pgvector/pgvector（README）、arxiv.org/abs/2210.07316
个性化 RAG 与用户向量eBay = arXiv:2102.06156（2021-02-11，《Personalized Embedding-based e-Commerce Recommendations at eBay》）：把商品与用户嵌入同一向量空间，用户向量由内容特征与站内行为共同算出；论文同时把它作为缓解大市场冷启动的手段，并用数据消融（data ablation）提升生产系统鲁棒性。RAG 侧的对应做法是把用户向量与 query 向量融合（融合权重应由画像置信度决定）。CoALA = arXiv:2309.02427（2023-09-05，Sumers 等）给出工作记忆 + 长期记忆的语义 / 情节 / 程序三分。工程红线：作用域过滤必须先于语义排序；语义缓存的键必须包含用户特征，否则个性化请求会串味"个性化就是把用户信息塞进 prompt"（那只影响生成、不影响召回）/ "用户画像是静态且永远正确的" / "私有库与公共库混在一个向量空间靠 rerank 区分" / "语义缓存命中率越高越好"（个性化场景下会串味）arxiv.org/abs/2102.06156、arxiv.org/abs/2309.02427

「规范定稿 / Chrome 推出 / Baseline」三者不可互相替代——这是本库最容易写出自相矛盾答案的地方。典型反例：Anchor Positioning 的 anchor() 在 Chrome 125 已有，但整体 Baseline = false；View Transitions 已是 Baseline low，但 Firefox 至今没有 @view-transition 规则。
